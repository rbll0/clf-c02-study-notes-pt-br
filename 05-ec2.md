EC2 aluga **servidores virtuais** (instâncias) por tempo de uso. Você escolhe CPU, RAM, storage e rede, e gerencia o sistema operacional. Por isso o EC2 é **IaaS**.

## A O que compõe uma instância {span=2}
```flow LR
(AMI: imagem) -> *Instância EC2: lança
Tipo de instância -> Instância EC2: define CPU e RAM
Instância EC2 -> [(EBS / Instance Store)]: disco
Instância EC2 -> Security Group: firewall
Key Pair -> Instância EC2: acesso SSH
```
- **AMI**: o modelo da instância (SO + software). Pode ser da AWS, do Marketplace ou sua.
- **Tipo de instância**: define CPU, memória, storage e rede.
- **User Data**: script que roda **uma vez**, no primeiro boot, como root.

## B Configurações ao criar
| Item | Opções |
|---|---|
| Sistema operacional | Linux, Windows ou macOS |
| CPU e RAM | Escolha pelo tipo da instância |
| Storage | EBS ou EFS (de rede), Instance Store (disco do hardware) |
| Rede | Placa de rede e IP público |
| Firewall | Security Group |
| Bootstrap | User Data |

## C Famílias de instância {span=3}
| Família | Prefixo | Otimizada para | Exemplo de uso |
|---|---|---|---|
| Uso geral | `t`, `m` | Equilíbrio entre CPU, RAM e rede | Servidores web, repositórios de código |
| Compute | `c` | CPU alta | Processamento em lote, ML, jogos, transcodificação |
| Memória | `r`, `x`, `z` | RAM alta | Bancos relacionais, cache, análise em tempo real |
| Storage | `i`, `d`, `h` | Disco local rápido (IOPS) | Data warehouse, bancos NoSQL |
| Computação acelerada | `p`, `g`, `f` | GPU e FPGA | Machine learning, gráficos |

O nome segue o padrão `m5.2xlarge`: `m` = família, `5` = geração, `2xlarge` = tamanho.

## D Security Groups {span=2}
Um Security Group é o **firewall virtual** da instância. Ele só tem regras de **permissão** e bloqueia o resto por padrão.

| Característica | Detalhe |
|---|---|
| Regras | Só `Allow`. Não existe `Deny` |
| Filtra por | Protocolo, porta e IP ou outro Security Group |
| Entrada (inbound) | Bloqueada por padrão |
| Saída (outbound) | Liberada por padrão |
| Escopo | Regional e ligado a uma VPC |
| Relação | Vários SGs por instância, e um SG em várias instâncias |
| Estado | Stateful: a resposta volta sozinha |

Ele **vive fora** da instância. Se a conexão dá **timeout**, o problema é o Security Group. Se dá **connection refused**, é a aplicação.

## E Portas que caem na prova
| Porta | Protocolo | Uso |
|---|---|---|
| 22 | SSH | Login em Linux |
| 21 | FTP | Envio de arquivos |
| 22 | SFTP | Envio de arquivos seguro (via SSH) |
| 80 | HTTP | Sites sem criptografia |
| 443 | HTTPS | Sites com criptografia |
| 3389 | RDP | Área remota em Windows |

## F Formas de conectar {span=3}
| Método | Sistema | Observação |
|---|---|---|
| SSH | Linux, Mac, Windows 10+ | Porta 22 aberta no Security Group |
| EC2 Instance Connect | Linux | Terminal no navegador, usa SSH por baixo |
| PuTTY | Windows antigo | Cliente SSH |
| RDP | Windows | Porta 3389 |

Guarde o `.pem` do Key Pair em segurança. Se você perder a chave privada, perde o acesso por SSH.

## G Modelos de compra {span=3}
| Modelo | Como funciona | Desconto | Melhor para |
|---|---|---|---|
| On-Demand | Paga por segundo (Linux) ou hora, sem compromisso | Nenhum | Carga curta e imprevisível |
| Reserved Instances | Compromisso de 1 ou 3 anos | Até 72% | Carga estável, como banco de dados |
| Convertible RI | RI que permite trocar o tipo | Até 66% | Carga estável que pode mudar |
| Savings Plans | Compromisso de gasto por hora (1 ou 3 anos) | Até 72% | Uso estável, com mais flexibilidade |
| Spot Instances | Capacidade ociosa. A AWS pode **interromper** | Até 90% | Lote, análise de dados, testes |
| Dedicated Hosts | Servidor físico **inteiro**, só seu | warn Mais caro | Licença por socket ou core, compliance |
| Dedicated Instances | Hardware só seu, sem controle do host | warn Mais caro | Isolamento de hardware |
| Capacity Reservations | Reserva de capacidade numa AZ, **sem** compromisso | Nenhum | Garantir capacidade em um período |

## H Dedicated Host vs Dedicated Instance
| | Dedicated Host | Dedicated Instance |
|---|---|---|
| Servidor físico completo | ok | no |
| Visibilidade de sockets e cores | ok | no |
| Controle de posicionamento | ok | no |
| Licenças por socket ou core | ok | no |
| Hardware compartilhado com outros clientes | no | no |

## I Spot: o que saber
- O desconto chega a **90%** sobre o On-Demand.
- Você define um preço máximo. Se o preço passar do seu limite, a AWS **interrompe** a instância.
- Use só para trabalho que **tolera falha**.
- **Nunca** use para banco de dados ou carga crítica.

## J Analogia do hotel (para decorar) {span=2}
| Modelo | Como no hotel |
|---|---|
| On-Demand | Você chega e paga a diária cheia |
| Reserved | Você fecha 1 ou 3 anos de estadia e ganha desconto |
| Savings Plan | Você promete gastar X por hora e usa onde quiser |
| Spot | Quarto vazio de última hora, mas pode ser pedido de volta |
| Dedicated Host | Você aluga o prédio inteiro |
| Capacity Reservation | Você reserva o quarto, mas paga a diária cheia mesmo sem usar |

```callout warn Pegadinhas de prova
- "Carga imprevisível e curta" = On-Demand.
- "Uso estável por anos" = Reserved ou Savings Plan.
- "Pode ser interrompido" = Spot.
- "Licença por socket ou core" = Dedicated Host.
- "Reservar capacidade sem compromisso" = Capacity Reservation.
- "Timeout" = Security Group.
- User Data roda só no **primeiro** boot.
```
